# 개인화 청취 앱 — 기초 지식 노트

학교 프로젝트용 정리. 지금의 청음 훈련 앱(How to Listen 리메이크 + USB DAC 실시간 출력)을 바탕으로
아래 7개 기능을 가진 앱으로 넓히기 위해 알아야 할 것들을 모은다.

1. 순음 청력 검사
2. 정위(소리 위치) 검사를 통한 HRTF / BRIR 개인화
3. 1·2의 결과로 최적화 EQ 프로필 생성
4. 그 EQ를 실시간 캡처 음원에 적용 (이미 있는 경로)
5. 청음 훈련 (이미 있음)
6. 귓바퀴 치수 등을 입력받아 머신러닝으로 HRTF 추정
7. HRTF를 이용한 개인화 음장 효과 (XBass/XSpace류, 진공관 음색)

각 절은 **개념 → 이 프로젝트에서 현실적으로 가능한 것 → 주의할 점 → 더 읽을 것** 순서다.
"⚠"는 계획을 바꿀 수도 있는 중요한 제약이다.

## 0. 공통 바탕지식

### 0.1 신호처리
| 개념 | 왜 필요한가 | 지금 코드에 있는가 |
|---|---|---|
| 샘플링, 나이퀴스트, 앨리어싱 | 진공관 음색 같은 비선형 처리는 고조파를 만들어 앨리어싱을 일으킨다 | 개념만 |
| 임펄스 응답(IR)과 전달함수 | HRTF, BRIR, 헤드폰 응답이 전부 IR/전달함수다 | — |
| FFT, 스펙트럼, 1/N 옥타브 스무딩 | 측정 결과를 보고 EQ 목표를 만들 때 | `core/dsp/Fft.kt` |
| 바이쿼드(RBJ) 필터: peaking, shelf, LP/HP | EQ 프로필의 기본 단위 | `core/dsp/Biquad.kt` |
| 컨볼루션, 특히 **분할 FFT 컨볼루션**(uniformly partitioned overlap-save) | HRIR/BRIR을 실시간으로 거는 유일한 현실적 방법. BRIR은 수천~수만 탭이라 직접 합성곱은 불가능 | 없음 — 새로 만들어야 함 |
| 최소위상(minimum phase) + 순수 지연 | HRIR을 "최소위상 필터 + ITD 지연"으로 쪼개면 보간·개인화가 쉬워진다 | — |
| 지수 사인 스윕(ESS) 측정법 (Farina, 2000) | 스피커/헤드폰/귀 응답을 직접 측정할 때의 표준 방법 | — |

### 0.2 심리음향
- **dB SPL / dB HL / dBFS 구분** — dBFS는 디지털 값, dB SPL은 실제 음압, dB HL은 "정상 청력 평균 대비"다.
  앱이 아는 건 dBFS뿐이다. 이 차이가 1번 기능의 가장 큰 제약이다 (§1).
- **등청감곡선** (ISO 226) — 같은 dB라도 주파수마다 크기가 다르게 들린다. 음량을 바꾸면 EQ 체감도 바뀐다.
- **임계대역 / ERB** — 귀의 주파수 해상도. EQ를 얼마나 촘촘하게 만들지의 근거.
- **마스킹** — 주변 소음이 청력 검사를 망친다.
- **두 귀 단서(Duplex theory)** — 저역은 ITD(양이 시간차), 고역은 ILD(양이 레벨차)로 좌우를 판단한다.
- **스펙트럼 단서** — 위/아래, 앞/뒤는 주로 귓바퀴가 만드는 고역(대략 4 kHz 이상)의 홈과 봉우리로 판단한다.
  같은 ITD·ILD를 갖는 점들의 집합이 **혼동 원뿔(cone of confusion)** 이고, 남의 HRTF를 쓰면
  **앞뒤 혼동, 위아래 왜곡, 머릿속 정위(외재화 실패)** 가 생긴다. 2·6번 기능이 해결하려는 문제가 바로 이것이다.

### 0.3 실험 설계와 평가
- 블라인드, 무작위 순서, 반복 — 지금 훈련 앱의 채점·난이도 사다리를 그대로 활용할 수 있다.
- **ABX**, **MUSHRA** (ITU-R BS.1534) — "개인화 EQ/HRTF가 정말 나은가"를 보이는 표준 청취 시험.
- 정위 평가 지표: 방위각·고도각 오차, 앞뒤 혼동률, 외재화 점수.
- HRTF 추정 지표: **LSD**(log-spectral distortion, dB).
- 학교 프로젝트라면 "몇 명에게, 어떤 조건으로, 어떤 지표로 비교했다"가 결과보다 더 중요하게 평가될 수 있다.

### 0.4 안전과 윤리
- ⚠ **의료기기가 아니다.** 청력 "검사"가 아니라 "선별/자가 확인"이라고 표현하고, 이상이 있으면 이비인후과를 권하는 문구를 둔다.
- 청력 손실 보정 EQ는 고역을 크게 올리기 쉬워서 **오히려 청력을 해칠 수 있다** → 최대 부스트 상한, 전체 음량 상한, 프리앰프 감쇠 필수.
- 귀 사진·두부 치수는 **생체정보**다. 기기 안에서만 처리하고, 수집한다면 동의서를 받는다.

## 1. 순음 청력 검사 (Pure-tone audiometry)

### 개념
- 125/250/500/1k/2k/4k/8k Hz(필요하면 3k, 6k) 순음을 한쪽 귀씩 들려주고, 들리는 가장 작은 레벨(역치)을 찾는다.
- 결과는 **청력도(audiogram)**: 가로 주파수, 세로 dB HL.
- 표준 절차는 **수정 Hughson-Westlake법**이다. 들리면 10 dB 내리고, 안 들리면 5 dB 올린다.
  **올라가는 방향으로 3번 중 2번** 들린 최저 레벨을 역치로 잡는다. 근거 규격은 ISO 8253-1, ASHA 지침이다.
  (단계 크기와 판정 기준은 일반적으로 알려진 값이다. 보고서에 쓸 때는 규격 원문으로 확인할 것.)
- 앱에서는 이 절차를 **적응형 계단법**으로 구현할 수 있다. 훈련 엔진에 이미 Levitt 계단법이 있다.

### ⚠ 핵심 제약: 보정(calibration)
- dB HL을 정확히 내려면 "이 dBFS가 고막에서 몇 dB SPL인가"를 알아야 한다.
  병원 청력계는 규격 헤드폰과 기준값(RETSPL; 헤드폰 종류별 ISO 389 시리즈)으로 보정되어 있다.
- 폰 + 아무 이어폰으로는 그 값을 모른다. 그래서 현실적인 선택지는 셋이다.
  1. **상대 청력도** — "이 이어폰으로 들었을 때 주파수별 역치". EQ를 만드는 데에는 사실 이것으로 충분하다.
     이어폰의 주파수 특성까지 함께 섞여 들어가는데, 3번 EQ의 목적이 "이 이어폰 + 이 귀"를 보정하는 것이라 오히려 맞다.
  2. **근사 보정** — 우리 앱은 USB DAC(BTR13) 경로를 직접 쥐고 있으므로 다음이 모두 "알 수 있는 값"이다.
     DAC 출력 전압(사양) × 헤드폰 감도(dB/mW 또는 dB/V, 측정 데이터베이스) × 우리가 보낸 dBFS → 대략적인 dB SPL.
     오차는 ±수 dB 이상이다.
  3. **정상 청력자 기준 정규화** — 정상 청력인 사람 여러 명의 역치 평균을 0으로 잡는다. 표본이 적으면 부정확하다.
- 주변 소음: 폰 마이크로 검사 전 소음 레벨을 재서 너무 시끄러우면 검사를 막는다.
  ISO 8253-1이 허용 배경소음 기준을 다룬다.
- 차폐(masking): 양쪽 청력 차이가 크면 반대쪽 귀가 대신 듣는다(교차 청취). 이어폰에서는 이 문제가 줄지만 0은 아니다.

### 지금 코드에서 쓸 것
- `SignalGenerator`(순음 생성), 페이드 처리, `PlaybackEngine`, USB 출력 경로(정확한 레벨을 보장한다 — 안드로이드 믹서의 볼륨/효과를 우회).
- 훈련 엔진의 Levitt 계단법(`core/training`).

### 더 읽을 것
- ISO 8253-1 (청력 측정 방법), ISO 389 시리즈 (기준 역치), ISO 226 (등청감곡선)
- ASHA, *Guidelines for Manual Pure-Tone Threshold Audiometry* (2005)
- 상용 예: Mimi Hearing, Samsung *Adapt Sound*, Apple *Headphone Accommodations* — 모두 "검사 → 개인 EQ" 구조다.

## 2. 정위 검사를 통한 HRTF / BRIR 개인화

### 개념
- **HRTF**(Head-Related Transfer Function): 특정 방향의 소리가 머리·귓바퀴·어깨를 거쳐 고막에 도착할 때의 필터.
  시간 영역 표현은 **HRIR**이다. 방향마다(방위각×고도각) 왼쪽·오른쪽 한 쌍씩 있다.
- **BRIR**(Binaural Room IR): HRIR + 방의 반사·잔향. "그 방의 그 스피커가 내 귀에서 어떻게 들리는가".
  헤드폰으로 스피커처럼 듣게 하는 데(외재화)에는 BRIR이 HRIR보다 훨씬 효과적이다.
- 저장 표준은 **SOFA** 형식(AES69)이다. 공개 데이터베이스가 대부분 SOFA로 배포된다.

### ⚠ 핵심 제약: "정위 검사로 HRTF를 측정"할 수는 없다
정위 검사는 HRTF를 **측정**하지 못한다. 할 수 있는 것은 **선택·조정**이다. 길은 두 가지다.

**A. 데이터베이스에서 고르기 (마이크 없이 가능, 추천)**
1. 공개 DB(아래 표)에서 HRTF 후보 N개를 고른다.
2. 각 후보로 여러 방향의 소리를 만들어 들려주고, 사용자가 위치를 답하게 한다.
   지금 훈련 앱의 문제·답·채점 구조를 그대로 쓸 수 있다.
3. 정위 오차·앞뒤 혼동·머릿속 정위가 가장 적은 후보를 고른다.
   - 선호도 평가로 고르는 방법도 있다 (Katz & Parseihian, 2012: 46개 HRTF를 평가해 소수의 대표 집합으로 줄임).
   - 최근에는 "가장 좋은 HRTF 하나"보다 **방향별로 다른 후보를 고르는** 쪽이 고도각 정확도를 높인다는 보고도 있다 (Goldring et al., 2024).
4. 그 위에 **ITD를 머리 크기로 개인화**한다. Woodworth 구형 머리 모델이 쓰인다.
   `ITD ≈ (a/c)(θ + sin θ)` (a: 머리 반지름, c: 음속, θ: 방위각)
   머리 반지름은 머리 폭·깊이·높이로 추정할 수 있다 (Algazi et al., 2001).
   그 논문을 인용한 2차 자료에 따르면 `r ≈ 0.51·(폭/2) + 0.019·(높이/2) + 0.18·(깊이/2) + 32 mm`이다.
   원문으로 계수를 확인할 것.

**B. 직접 측정 (하드웨어 필요)**
- 귓구멍 입구에 넣는 **바이노럴 인이어 마이크** + 스피커 + 지수 사인 스윕으로 BRIR을 측정한다.
- 공개 구현 **Impulcifer**(jaakkopasanen)가 이 과정을 그대로 한다.
  측정 결과는 HeSuVi용 파일로 나오고, 같은 마이크로 헤드폰 응답을 재서 헤드폰 보정까지 한다.
  단, 입구 마이크로는 헤드폰이 외이도 공명에 주는 영향을 잴 수 없다는 한계가 문서에 적혀 있다.
- 우리 앱은 USB 오디오를 직접 다루므로 USB 마이크 입력을 받는 것도 같은 기술 범위다. 다만 **마이크를 사야 한다.**

## 3. 최적화 EQ 프로필 생성

EQ는 서로 다른 세 가지 목적을 겹쳐 만든다. 셋을 섞지 말고 **층으로 나눠 설계**하는 것이 핵심이다.

```
최종 EQ = [헤드폰 보정] + [청력 보정(부분)] + [취향/타깃]   → 바이쿼드 N개로 근사 → 프리앰프 감쇠
```

### 3.1 헤드폰 보정 → 타깃 곡선
- **Harman 타깃**: 실내 스피커 응답을 바탕으로 만든 헤드폰 선호 곡선이다.
  Olive, Welti & McMullin(2013)에서 가장 선호되었고, 2018년에 Olive, Welti & Khonsaripour가
  "타깃에서 얼마나 벗어났는가로 선호도를 예측"하는 모델을 냈다.
- **AutoEq**(jaakkopasanen): 수천 개 헤드폰 측정치를 타깃에 맞추는 파라메트릭 EQ를 자동 생성한다.
  측정 데이터와 알고리즘이 공개되어 있어서 그대로 참고할 수 있다.
- 사용자의 헤드폰 모델만 알면 이 층은 측정 없이 데이터만으로 만들 수 있다.

### 3.2 청력 보정
- ⚠ **역치 차이를 그대로 올리면 안 된다.** 감각신경성 난청에는 **누가 현상(loudness recruitment)** 이 있어서,
  작은 소리는 안 들려도 큰 소리는 정상처럼 크게 들린다. 역치 손실만큼 다 올리면 큰 소리가 너무 커진다.
- 보청기 처방식은 **부분 보상**을 한다.
  - 고전적 경험칙: 손실의 약 절반만 보상하는 half-gain rule
  - 정식 처방: **NAL-NL2**, **DSL v5** (입력 레벨에 따라 이득이 달라지는 비선형 = 다채널 압축)
- 학교 프로젝트 수준의 현실적 설계:
  - 손실의 일부(예: 1/3~1/2)만 보상한다.
  - 부스트 상한(예: +10 dB)을 둔다.
  - 좌우 따로 적용한다.
  - 더 가고 싶으면 대역별 압축을 쓴다 (`core/dsp/artifacts/Compression.kt` 활용).

### 3.3 HRTF와 EQ의 관계
- 2번에서 고른 HRTF를 7번 음장 효과에 쓰면, 그 HRTF가 이미 귀의 스펙트럼 특성을 담고 있다.
  그래서 **확산음장(diffuse-field) 평균을 빼서** 정규화해야 이중으로 적용되지 않는다.
- 헤드폰 보정 타깃(Harman)도 확산음장/실내 응답에 바탕을 둔다. 두 층이 같은 것을 두 번 보정하지 않게 기준을 맞춰야 한다.

### 3.4 곡선 → 필터
- 목표 곡선을 1/6~1/3 옥타브로 스무딩한다.
- 파라메트릭 EQ(peaking + shelf) N개를 탐욕적 또는 최소제곱 방식으로 맞춘다 (AutoEq 방식 참고).
- Q와 이득에 상한을 둔다.
- 최대 부스트만큼 **프리앰프를 감쇠**해 클리핑을 막는다.
- 결과는 지금 엔진의 `AudioProcessor` 하나로 만들어 바이쿼드를 직렬로 연결하면 된다 (`Biquad.kt`).

## 6. 귓바퀴 치수 → 머신러닝 HRTF 추정

### 접근법 (쉬운 것부터)
1. **최근접 이웃 선택** — 사용자 치수와 가장 비슷한 DB 피험자의 HRTF를 고른다. 구현이 쉽고 기준선(baseline)으로 좋다.
2. **PCA + 회귀** — HRTF(로그 크기 스펙트럼)를 PCA로 압축하고, 치수로 주성분 가중치를 회귀한다. 고전적 방법이다.
3. **DNN** — 치수로 HRTF 크기 스펙트럼을 직접 예측한다.
   - Lee & Kim (2018, *Applied Sciences* 8(11):2180):
     머리·몸통 치수는 DNN, **귀 사진은 CNN**으로 처리하고 두 특징을 합쳐 개인 HRTF를 추정했다.
     평균 HRTF, 치수만 쓴 DNN과 비교했고 정위 청취 시험도 했다.
     귀 치수는 실제로 재기 어렵다는 점이 사진을 쓴 동기였다.
4. **3D 스캔 → 수치 시뮬레이션** — 머리 메시로 경계요소법(BEM) 계산을 한다 (Mesh2HRTF).
   정확하지만 무겁다. 상용 사례: Apple 개인화 공간 음향(TrueDepth 스캔), Sony 360RA(귀 사진).

### 입력 치수 (CIPIC 정의)
- 머리·몸통 17개: 머리 폭·높이·깊이, 목, 어깨 폭 등
- 귓바퀴 10개: 갑개강 높이·폭, 귀 높이·폭, 귀 회전각, 귀 벌어짐 각 등
- 학교 프로젝트에서는 **줄자·자로 재기 쉬운 몇 개 + 귀 사진**이 현실적이다. 측정 방법을 그림으로 안내하는 화면이 필요하다.

### ⚠ 현실적인 기대치
- 데이터가 작다. CIPIC 45명, SONICOM 수백 명 → 과적합이 쉽고, 교차검증(leave-one-subject-out)이 필수다.
- 위상은 학습시키지 않는다. 보통 **크기 스펙트럼만 학습**하고 위상은 최소위상 + ITD(§2의 Woodworth)로 다시 붙인다.
- 평가: LSD(dB)로 "평균 HRTF보다 나은가"를 보고, 반드시 §2의 정위 검사로 **청취 결과**까지 확인한다.
- 학습은 PC(Python: PyTorch/scikit-learn)에서 하고, 앱에는 작은 모델만 넣는다 (TFLite/ONNX).
  최근접 이웃이나 PCA 회귀라면 앱 안에서 행렬 곱 몇 번으로 끝난다.

## 7. 개인화 음장 효과

### 7.1 공간화
- **크로스피드** (Bauer, Linkwitz): 반대쪽 채널을 저역 통과·지연시켜 섞는다. 가장 가볍고, 헤드폰의 과한 좌우 분리를 줄인다.
- **가상 스피커**: 스테레오 L/R을 ±30° 스피커 위치의 HRIR/BRIR로 각각 컨볼루션해서 더한다.
  2번에서 고른 개인 HRTF를 쓰면 이것이 "개인화 음장"이 된다.
  잔향(BRIR 또는 합성 잔향, `Reverb.kt`)을 더하면 외재화가 크게 좋아진다.
- 참고로 상용 제품 이름과 실제 기능:
  - **iFi XBass**: 아날로그 **저역 셸빙 부스트**. 헤드폰에서 빠지는 저역을 "되돌리는" 용도이고, 크로스피드가 아니다.
  - **iFi XSpace**: 헤드폰 음장을 스피커처럼 넓히는 아날로그 매트릭스 회로. iFi 고유 방식으로, 전통적 Bauer/Linkwitz 크로스피드와는 다르다고 한다.
  - 우리는 디지털로 같은 목적을 구현한다. XBass → 저역 셸프 바이쿼드, XSpace → 크로스피드 또는 개인 HRTF 가상 스피커.
- 심리음향 저역(MaxxBass류): 기본음 대신 고조파를 만들어 "작은 이어폰에서 저역이 있는 것처럼" 들리게 한다. 실제 부스트보다 안전하다.

### 7.2 진공관 음색
- 핵심은 **고조파 구성**이다. 싱글엔디드 3극관은 2차 고조파가 지배적이다(짝수차 → "따뜻함").
  비대칭 소프트 클리핑으로 만들 수 있고, 지금 `Distortion.kt`에 비대칭 바이어스 방식이 있다.
- 출력 트랜스의 저역·고역 감쇠, 큰 신호에서의 전원 처짐(sag, 입력 의존 압축)까지 넣으면 더 그럴듯해진다.
- ⚠ 비선형 처리는 앨리어싱을 만든다 → **오버샘플링**(2~4배) 후 처리하고 다시 내린다.
- 정밀 모델링(Koren 3극관 모델, 회로 시뮬레이션)은 프로젝트 범위를 넘는다. 고조파 프로파일 매칭이면 충분하다.

### 7.3 순서
```
캡처 → [헤드폰+청력 EQ] → [음색: 진공관] → [공간: 크로스피드 / HRTF 가상 스피커 + 잔향] → [안전 리미터] → USB DAC
```
- 공간 처리 뒤에 EQ를 두면 HRTF 특성까지 EQ가 "고쳐버린다". 그래서 EQ는 앞에 둔다.
- 컨볼루션 + 오버샘플링은 CPU를 많이 쓴다. 분할 FFT 컨볼루션은 Kotlin으로도 가능하지만, 필요하면 C++(NDK)로 옮긴다.
  NDK 빌드는 이미 갖춰져 있다.

## 8. 범위와 우선순위 제안

7개 기능은 대학원 연구실 프로젝트 여러 개에 해당하는 분량이다. 학교 프로젝트로 끝까지 가려면 이렇게 묶는 것을 추천한다.

| 우선 | 기능 | 이유 |
|---|---|---|
| 이미 있음 | 4, 5 | v0.3 실기 검증만 남음 |
| 1순위 | **1 (상대 청력도) → 3 (헤드폰 보정 + 부분 청력 보정 EQ)** | 하드웨어 추가 없이 끝까지 닿는 한 줄기. 효과를 ABX로 증명하기 쉽다 |
| 2순위 | **7.1 크로스피드 + 공개 HRTF 가상 스피커**, 7.2 진공관 | 컨볼루션 엔진 하나만 만들면 된다 |
| 3순위 | **2A (DB에서 HRTF 고르기 + ITD 개인화)** | 정위 검사 UI는 훈련 엔진 재사용 |
| 도전 | **6 (최근접 이웃 → PCA 회귀 → 가능하면 DNN)** | 데이터 작업이 많다. 2A와 같은 정위 검사로 평가하면 이야기가 이어진다 |
| 선택 | 2B (인이어 마이크로 BRIR 직접 측정) | 마이크 구매가 필요 |

### 새로 만들어야 하는 핵심 부품
1. 순음 생성기 + 적응형 역치 탐색 + 청력도 화면
2. EQ 설계기: 목표 곡선 → 파라메트릭 바이쿼드 맞춤
3. **분할 FFT 컨볼루션 엔진** (HRIR/BRIR, 실시간)
4. SOFA 파일 읽기 (HDF5/netCDF 기반이라 앱에서는 미리 변환한 단순 포맷을 쓰는 것이 낫다)
5. 처리 체인 구조 개편: "항상 켜진 체인" + "훈련용 아티팩트"
6. (6번) PC 쪽 Python 학습 파이프라인 + 앱용 경량 모델
